# Agent Performance Dashboard

Full spec: [`CLAUDE.md`](./CLAUDE.md). Read that first — it explains *why*
every rule below exists.

## Quick start

```
pip install -r requirements.txt

# drop today's exports into input/:
#   input/Production_Report_YYYY-MM-DD.xlsx
#   input/kp-leads-YYYY-MM-DD.csv
#   input/Marketing_KPI_Vendor_Report_-_Detail.xlsx
#   input/YesUCan_Agent_Tracker.xlsx

python build.py                    # writes data/agents.json + data/summary.json
python build.py --agent MP120      # print one agent's numbers to the terminal
```

If any reconciliation check fails, `build.py` exits non-zero and prints the
diff — it never writes JSON silently on a bad build.

## Frontend

Static, no server. From the repo root:

```
python -m http.server 8000
```

then open `http://localhost:8000/web/index.html` (agent view) or
`http://localhost:8000/web/manager.html` (manager view). Both fetch
`../data/agents.json` and `../data/summary.json` at load time.

## Tests

```
pytest
```

`tests/fixtures/` holds a small synthetic set of the four source files
(regenerate with `python tests/fixtures/make_fixtures.py`) built specifically
to exercise the alias table, cross-month bk_Ref attribution, zero-value
exclusion, and reconciliation from CLAUDE.md's acceptance tests.

## Layout

```
input/            # daily exports land here (git-ignored — real customer data)
build.py          # parses, normalises, reconciles, emits JSON
aliases.json      # agent-code alias map — extend this, not build.py
data/             # generated by build.py (git-ignored)
web/              # static frontend
tests/            # pytest suite + synthetic fixtures
```
